Project Structure

Folder responsibilities and why this layout is used.

Tree

index.js src/ app.js config/ db.js controllers/ authController.js userController.js middlewares/ authMiddleware.js models/ User.js routes/ authRoutes.js userRoutes.js utils/ generateToken.js tests/ setup.js health.test.js auth/ register.test.js login.test.js protect.test.js docs/ ... (architecture and API docs) docs-site/ ... (static site you are reading)

Responsibilities

  • index.js: Entry point. Loads env, connects DB, starts server.
  • src/app.js: Builds Express app, applies middleware, mounts routers, health checks.
  • config/: DB connection helpers.
  • routes/: URL to controller mapping; no business logic.
  • controllers/: Request handling logic, validation, DB orchestration.
  • models/: Mongoose schemas, validation, hooks (e.g., password hashing).
  • middlewares/: Cross-cutting concerns (auth guard).
  • utils/: Focused helpers (JWT token generation).
  • tests/: Jest + Supertest suites validating API behavior.
  • docs/: Markdown docs; docs-site/ is this static site.

Why This Layout

  • Keeps HTTP boundary (routes) separate from business logic (controllers).
  • Models remain single-source-of-truth for data shape and hashing.
  • Middlewares remain reusable and composable.
  • Tests live next to features for discoverability.
