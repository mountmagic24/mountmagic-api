Architecture & Request Flow

How the backend is layered and how requests travel through it.

Layered Design

  • Entry: index.js loads env, connects DB, starts Express.
  • App: app.js builds Express instance, JSON middleware, mounts routers.
  • Routes: map HTTP verbs/paths to controllers; no business logic.
  • Middleware: auth guard attaches user for protected routes.
  • Controllers: validate, orchestrate models, craft responses.
  • Models: Mongoose schemas with validation and hooks (password hashing).
  • Database: MongoDB Atlas (URI via env).
  • Tests: Jest + Supertest assert contract at HTTP boundary.

Protected requests must carry Authorization: Bearer <token>. Middleware verifies token and loads the user. Controllers trust req.user when present and perform domain logic.

Error and Security Posture

  • 401 for missing/invalid JWT (middleware) or no user match.
  • 400 for missing required fields at controller level.
  • 404 for not found or invalid ObjectId.
  • 409 for duplicate resources (email uniqueness).
  • Password hashing in model pre-save hook; never returned.

Why this Architecture

  • Predictable separation of concerns improves readability and onboarding.
  • Auth concerns centralized in one middleware instead of scattered checks.
  • Models encapsulate hashing to prevent controller mistakes.
  • Tests at HTTP boundary guarantee integration correctness.
