## 1. Users Collection

The Users collection stores all registered users of the platform.

Each user represents a person who can access the system using authentication.

This collection is responsible for storing identity information, authentication provider, role assignments, and basic profile details.

Users interact with different services in the system such as blog posting, taxi booking requests, and CS center document services.

### Fields

- `_id`  
  Unique identifier automatically generated by MongoDB.

- `name`  
  Full name of the user.

- `email`  
  Email address used for authentication and communication.

- `authProvider`  
  Authentication provider used for login.  
  Example values:
  - google

- `role`  
  Role assigned to the user which determines system permissions.  
  Example values:
  - admin
  - taxi_manager
  - cs_center_manager
  - content_manager
  - user

- `profileImage`  
  URL of the user's profile image stored on Cloudinary or another media storage service.

- `createdAt`  
  Timestamp representing when the user account was created.

- `updatedAt`  
  Timestamp representing the last update made to the user profile.

---

### Example User Document

```json
{
  "_id": "ObjectId",
  "name": "Devansh Bhardwaj",
  "email": "devansh@gmail.com",
  "authProvider": "google",
  "role": "admin",
  "profileImage": "https://cloudinary.com/profile-image",
  "createdAt": "2026-03-23T10:00:00Z",
  "updatedAt": "2026-03-23T10:00:00Z"
}
```

## 2. BlogPosts Collection

The BlogPosts collection stores all travel blogs published on the platform.

These blogs can include travel experiences, hidden locations in Himachal Pradesh, guides, or informational articles related to tourism.

Each blog post is associated with a user who acts as the author of the content.

The blogging system allows the platform to build useful travel information while also increasing engagement with visitors.

Blog posts may include text content, images, and publishing metadata.

### Fields

- `_id`  
  Unique identifier automatically generated by MongoDB.

- `title`  
  Title of the blog post.

- `content`  
  Main body text of the blog article.

- `authorId`  
  Reference to the user who created the blog post.  
  This field stores the `_id` of the user document.

- `coverImage`  
  URL of the main image associated with the blog post.  
  Images will be stored in Cloudinary or another external storage service.

- `images`  
  Optional array containing URLs of additional images used inside the blog.

- `status`  
  Indicates the publishing status of the blog.  
  Example values:
  - draft
  - published

- `tags`  
  Array of keywords related to the blog post.  
  Example:
  - himachal
  - trekking
  - hidden places

- `createdAt`  
  Timestamp indicating when the blog was created.

- `updatedAt`  
  Timestamp indicating the last modification of the blog post.

---

### Example Blog Document

```json
{
  "_id": "ObjectId",
  "title": "Hidden Waterfall Near Hamirpur",
  "content": "This location is one of the lesser known waterfalls in Himachal Pradesh...",
  "authorId": "ObjectId",
  "coverImage": "https://cloudinary.com/blog-cover.jpg",
  "images": [
    "https://cloudinary.com/img1.jpg",
    "https://cloudinary.com/img2.jpg"
  ],
  "status": "published",
  "tags": ["himachal", "waterfall", "travel"],
  "createdAt": "2026-03-23T11:00:00Z",
  "updatedAt": "2026-03-23T11:00:00Z"
}
```

## 3. TaxiRequests Collection

The TaxiRequests collection stores requests made by users who want transportation services through the platform.

This service is designed for travelers who need taxi assistance while planning trips to destinations such as Manali, Shimla, or other locations in Himachal Pradesh.

Users can submit a request specifying their pickup location, destination, travel date, and other details.

The system administrators or taxi managers can review these requests and respond accordingly.

This system does not function as an automated ride-hailing service but rather as a request management system handled by the platform staff.

### Fields

- `_id`  
  Unique identifier automatically generated by MongoDB.

- `userId`  
  Reference to the user who submitted the taxi request.  
  This field stores the `_id` of the user document.

- `pickupLocation`  
  Starting location of the journey.

- `destination`  
  Destination location requested by the user.

- `travelDate`  
  Date on which the user wants to travel.

- `passengerCount`  
  Number of passengers traveling.

- `driverFoodIncluded`  
  Boolean field indicating whether the user agrees to cover the driver's meal expenses.

- `estimatedFare`  
  Estimated cost calculated by the admin or taxi manager.

- `status`  
  Current status of the taxi request.  
  Example values:
  - pending
  - reviewed
  - approved
  - rejected
  - completed

- `notes`  
  Optional message from the user or admin regarding the request.

- `createdAt`  
  Timestamp representing when the request was submitted.

- `updatedAt`  
  Timestamp representing the last update to the request.

---

### Example Taxi Request Document

```json
{
  "_id": "ObjectId",
  "userId": "ObjectId",
  "pickupLocation": "Hamirpur",
  "destination": "Manali",
  "travelDate": "2026-04-10",
  "passengerCount": 3,
  "driverFoodIncluded": true,
  "estimatedFare": 5500,
  "status": "pending",
  "notes": "Need early morning departure",
  "createdAt": "2026-03-23T12:00:00Z",
  "updatedAt": "2026-03-23T12:00:00Z"
}
```

## 4. DocumentServiceRequests Collection

The DocumentServiceRequests collection stores requests submitted by users who need assistance with document-related services provided by the CS Center (Lokmitra Kendra).

These services may include Aadhaar updates, document printing, government form assistance, and other document-related tasks.

Users can submit a request through the website and upload necessary files. The CS Center staff can then review the request, process the documents, and update the request status.

This system helps the business manage document services efficiently while keeping records of all requests.

### Fields

- `_id`  
  Unique identifier automatically generated by MongoDB.

- `userId`  
  Reference to the user who created the request.  
  This stores the `_id` from the Users collection.

- `serviceType`  
  Type of service requested.  
  Example values:
  - aadhaar_update
  - document_print
  - government_form
  - other

- `description`  
  Additional details provided by the user describing the request.

- `documents`  
  Array containing URLs of uploaded files.  
  Files are stored using an external storage service such as Cloudinary.

- `contactNumber`  
  Phone number provided by the user for communication.

- `priceEstimate`  
  Estimated cost of the service determined by the CS Center staff.

- `paymentStatus`  
  Status of payment for the request.  
  Example values:
  - pending
  - paid
  - not_required

- `requestStatus`  
  Current processing status of the request.  
  Example values:
  - submitted
  - processing
  - completed
  - rejected

- `createdAt`  
  Timestamp indicating when the request was created.

- `updatedAt`  
  Timestamp indicating the last update made to the request.

---

### Example Document

```json
{
  "_id": "ObjectId",
  "userId": "ObjectId",
  "serviceType": "aadhaar_update",
  "description": "Need to update mobile number in Aadhaar",
  "documents": ["https://cloudinary.com/document1.jpg"],
  "contactNumber": "9876543210",
  "priceEstimate": 150,
  "paymentStatus": "pending",
  "requestStatus": "submitted",
  "createdAt": "2026-03-23T12:30:00Z",
  "updatedAt": "2026-03-23T12:30:00Z"
}
```
